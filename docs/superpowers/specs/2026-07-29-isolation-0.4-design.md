# Telezon-S3 0.4 — Multi-tenant Isolation Design

**Date:** 2026-07-29  
**Status:** Auto-approved (phase gate)  
**Depends on:** 0.2 + 0.3

## Goal

Improve logical isolation and controlled public access without Cloudflare Mini App complexity.

## Scope (this phase)

1. **Bucket Telegram destination** — optional `telegram_chat_id` + `telegram_topic_id` on bucket; Account/Bot storage use per-bucket destination when set, else fall back to global `CID`.
2. **Public buckets** — `is_public: bool` on bucket; unauthenticated GET/HEAD for public buckets only (PUT/DELETE still require SigV4).
3. **Share links** — Mongo `shares` collection: token, bucket, key, optional password hash, expires_at, max_downloads, download_count.  
   - `POST /api/v1/shares` (JWT, owner/admin)  
   - `GET /share/{token}` download (password via query/header)  
   - `DELETE /api/v1/shares/{token}` revoke
4. Version **0.4.0** + S3-COMPAT updates.

## Non-goals

- Full Mini App / share HTML preview pages (plain download endpoint is enough)
- Per-credential RBAC matrix beyond existing owner keys (defer)
- Multipart / SSE / cache

## Success criteria

- Public GET works without Authorization; private GET still 403
- Share create → download → expiry/max downloads enforced
- put_file/delete_message honor bucket topic when configured
- pytest coverage for public + share happy/deny paths
