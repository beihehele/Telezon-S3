# Telezon-S3 0.2 — S3 Protocol Completeness Design

**Date:** 2026-07-29  
**Status:** Approved (Approach 2)  
**Decisions locked:** Delete = Mongo required + TG best-effort; Presign GET+PUT; ListObjectsV2 + ListBuckets; store optional `message_id` on upload

## Goal

Make Telezon-S3 usable with standard S3 clients (boto3 / awscli / rclone) for everyday object lifecycle: upload, download, head, delete, list objects, list buckets, and time-limited presigned GET/PUT — without changing the product into a chat bot or Cloudflare Worker stack.

## Non-goals (explicit)

- S3 CreateBucket / DeleteBucket / DeleteObjects (multi)
- Multipart upload
- Versioning, ACL, bucket policy, tagging, lifecycle
- Cache layer, SSE encryption, Local Bot API, Mini App
- Streaming I/O / long-lived Pyrogram client (deferred to 0.3)
- SaveAny-Bot features (watch/copy/yt-dlp/multi-backend)

## Architecture

Keep FastAPI + MongoDB + existing SigV4 verifier. Split the monolithic `app/s3/__init__.py` into focused handlers and shared XML/error helpers. Extend the Storage ABC so uploads return enough Telegram identifiers to delete messages later.

```
S3 Client
  → FastAPI router (method + path + query dispatch)
      → auth: header SigV4 OR query-string presign
      → handler (put/get/head/delete/list/list-buckets)
          → crud (Mongo)
          → storage (Telegram put/get/delete_message)
      ← XML or binary response / S3 error XML
```

## Components

### 1. Storage contract

Change `put_file` to return a structured result instead of bare `file_id` string:

```python
class PutFileResult(BaseModel):
    file_id: str
    message_id: int | None = None
```

- `TelegramAccountStorage.put_file`: return `file_id` + `message.message_id`
- `TelegramBotStorage.put_file`: return `file_id` + `message.message_id`
- Add `delete_message(message_id: int) -> bool`: best-effort; log and return False on failure; never raise to callers of DeleteObject success path

Backward compatibility: callers that still need a string use `result.file_id`.

### 2. Blob model / Mongo

Add optional field on blob documents:

- `message_id: int | None = None` (default None for legacy rows)

CRUD:

- `crud_delete_blob(db, bucket_name, path) -> BlobInDb | None` — delete one matching doc, return deleted snapshot (for TG cleanup)
- `crud_list_blobs_for_s3(db, bucket_name, prefix, start_after, max_keys)` — path prefix match, sort by path ascending, support continuation via `start_after` / token encoding of last key
- Existing create/update stores `message_id` when present

No Mongo migration script: field is optional; old objects simply skip TG delete.

### 3. S3 routing

Replace single-file routes with dispatcher-friendly modules under `app/s3/`:

| Module | Responsibility |
|--------|----------------|
| `errors.py` | S3 XML error body (`Error/Code/Message/Resource/RequestId`) |
| `xml.py` | Escape + ListBuckets / ListBucketResult builders |
| `auth.py` | Wrap existing SigV4; add credential lookup by access_key for ListBuckets; presign verify |
| `presign.py` | Generate/verify query-string SigV4 (GET/PUT), max expiry 7 days |
| `handlers/object.py` | PUT/GET/HEAD/DELETE `/{bucket}/{key:path}` |
| `handlers/list_objects.py` | GET `/{bucket}` with `list-type=2` |
| `handlers/list_buckets.py` | GET `/` |
| `router.py` | Wire routes; preserve include in `main.py` |

**Dispatch rules:**

- `GET /` → ListBuckets (SigV4 against any valid access key → return buckets owned by that user)
- `GET /{bucket}?list-type=2` → ListObjectsV2 (require `list-type=2`; unsupported list-type → 501 NotImplemented XML)
- `GET/PUT/HEAD/DELETE /{bucket}/{key}` → object ops
- Object key: use FastAPI `{key:path}` so keys may contain `/`

**HEAD fix:**

- Require SigV4 (same as GET)
- Return empty body with headers: `Content-Length`, `Content-Type`, `ETag` (weak ok: `"size-updated_at"` or hash of `file_id`), `Last-Modified` if available
- 404 if missing

**DeleteObject:**

1. Verify SigV4 for bucket owner
2. Delete Mongo row; if none existed → still 204 No Content (S3 idempotent delete)
3. If deleted row had `message_id` → `storage.delete_message(message_id)` best-effort
4. Always 204 on auth success after metadata step

**Presigned URLs:**

- Generation helper used by optional `POST /api/v1/presign` (JWT auth, bucket owner or admin) returning `{url, expires_in}`
- Verification: if query has `X-Amz-Algorithm=AWS4-HMAC-SHA256`, validate query signature and expiry; skip header Authorization requirement
- Supported methods: GET, PUT only
- Max `X-Amz-Expires`: 604800 (7 days)

**ListObjectsV2 (minimal subset):**

Supported query params: `list-type=2`, `prefix`, `max-keys` (default 1000, clamp 1–1000), `continuation-token`, `start-after`.  
Unsupported in 0.2 (ignore or omit): `delimiter` / common prefixes (no delimiter support — flat key list only).  
Response: standard `ListBucketResult` XML with `Contents` (Key, LastModified, ETag, Size, StorageClass=STANDARD), `IsTruncated`, `NextContinuationToken`, `KeyCount`, `MaxKeys`, `Name`, `Prefix`.

**ListBuckets:**

- Auth: SigV4 with access_key → resolve user → list that user's buckets (admin credentials list only own buckets unless we resolve via owner mapping — keep simple: buckets where `owner_username` matches credential owner)
- XML `ListAllMyBucketsResult`

### 4. Error model

All S3 auth/object failures return application/xml:

| Condition | HTTP | Code |
|-----------|------|------|
| Bad signature / expired presign | 403 | SignatureDoesNotMatch / AccessDenied |
| Missing bucket | 404 | NoSuchBucket |
| Missing object (GET/HEAD) | 404 | NoSuchKey |
| Unimplemented subresource | 501 | NotImplemented |

Do not use JSON for S3 routes.

### 5. Testing

Add pytest (dev dependency) + httpx AsyncClient against FastAPI app with:

- Mongo: mongomock-motor or ephemeral test DB via env
- Storage: in-memory fake implementing put/get/delete_message

Tests (minimum):

1. PUT then GET roundtrip
2. HEAD returns Content-Length header and requires auth
3. DELETE removes object; second DELETE still 204
4. DELETE with message_id calls delete_message; without skips
5. ListObjectsV2 prefix + truncation/continuation
6. ListBuckets returns owner buckets
7. Presign GET works without Authorization header within expiry; fails after expiry

## Data flow — DeleteObject

```
DELETE /bucket/key + SigV4
  → load bucket + verify
  → crud_delete_blob → deleted | None
  → if deleted.message_id: storage.delete_message (catch/log)
  → 204
```

## Risks

| Risk | Mitigation |
|------|------------|
| Route `GET /{bucket}` vs `GET /{bucket}/{key}` ambiguity | Separate path params; list only when no key segment and list-type present or empty key route registered first |
| SigV4 query_string encoding mismatches for presign | Reuse/adjust existing verifier; golden tests with boto3 generate_presigned_url |
| Pyrogram delete_messages API differences | Account: `delete_messages(CID, message_id)`; Bot: `bot.delete_message(CID, message_id)` |
| Workers=4 + per-request clients | Out of scope for 0.2; document known limit |

## Success criteria

- `boto3` against custom endpoint can: `upload_file`, `download_file`, `head_object`, `delete_object`, `list_objects_v2`, `list_buckets`, `generate_presigned_url` (get/put)
- Legacy blobs without `message_id` still GET/HEAD/DELETE (metadata) without error
- pytest suite green in CI-ready layout (CI wiring can be follow-up if timeboxed)
